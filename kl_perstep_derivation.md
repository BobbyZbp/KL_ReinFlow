# Per-Step KL Derivation

## Setup

We sample noise once: `z = a^0 ~ N(0, I)` (line 651). The **theta-flow** (base + residual) generates the trajectory we follow:

```
a^{k+1} = a^k + v_theta(a^k, t_k) * dt        (line 668)
```

This produces a sequence of outputs `a^1, a^2, ..., a^{K-1}`. The per-step KL asks: how expensive is it for the reference flow to reproduce each of these outputs, step by step?


## Per-Step Inversion

At each step k, the theta-flow produces output `a^{k+1}` from input `a^k`. We find the input `a^k_inv` that the **ref-flow** (frozen base) would need to produce the same output:

```
a^k_inv + v_ref(a^k_inv, t_k) * dt = a^{k+1}
```

This is solved via `_one_step_fp_inversion` (lines 479-487): `perstep_fp_iters` rounds of fixed-point iteration under `torch.no_grad()` to get `a_inv_ng` (line 670), followed by one differentiable refinement `a_inv = a_next - v_ref(a_inv_ng) * dt` (lines 671-672) that provides a gradient path through `a_next` without backpropping through the FP loop.

Both maps produce the same output `a^{k+1}`, from different inputs (`a^k` vs `a^k_inv`).


## Per-Step Volume Change

At step k, each flow maps its input to `a^{k+1}`. The one-step map Jacobians are:

```
M^theta_k = I + (dv_theta/da)(a^k, t_k) * dt       → logdet_combined_k  (lines 710-711)
M^ref_k   = I + (dv_ref/da)(a^k_inv, t_k) * dt     → logdet_ref_k       (lines 716-717)
```

`log|det M_k|` measures how much that flow stretches space in one step. Larger logdet means more expansion, lower density.


## The Per-Step KL

**Modeling assumption:** the input densities at `a^k` and `a^k_inv` are treated as equal. This drops the density ratio term `log q_k(a^k) - log q_k(a^k_inv)` that a true one-step KL would include. The approximation is valid when `v_res` is small, and becomes exact as `dt -> 0`.

Under this assumption, the density ratio at `a^{k+1}` depends only on how much each flow stretches space:

```
log [q^theta_{k+1}(a^{k+1}) / q^ref_{k+1}(a^{k+1})]
    = log|det M^ref_k| - log|det M^theta_k|
    = logdet_ref_k - logdet_combined_k
```

The total per-step KL sums these contributions along the entire theta trajectory:

```
sum_kl = sum_{k=0}^{K-2} [logdet_ref_k - logdet_combined_k]       (line 720)
```

This is a path-level quantity. It does not compute the ref density at a single endpoint. It sums up, step by step, the volume-change cost for the ref flow to reproduce each output the theta flow produced. The ref logdets are evaluated at independently inverted points at each step, not along a single coherent ref trajectory.


## Consistency with Change of Variables

The standard change-of-variables formula `log p(a) = log p(z) - sum_k log|det J_k|` connects the per-step sum to endpoint log-densities:

```
log p_theta(a^{K-1}) = log p_0(z) - sum_k logdet_combined_k       (line 723)
```

Under the shared-noise and equal-density assumptions, an approximate ref density:

```
log p_ref(a^{K-1}) ≈ log p_0(z) - sum_k logdet_ref_k              (line 724, derived)
```

The `log p_0(z)` terms cancel because both flows start from the same noise, giving:

```
sum_kl = log p_theta - log p_ref
```

This has the sign of forward KL. Line 724 (`log_p_base = log_p_theta - sum_kl`) is bookkeeping consistent with this identity, but it is not the true endpoint `log p_ref` (that would need a full backward solve to find a separate `z_ref`).


## Forward KL

Forward KL is `KL(p_theta || p_ref) = E_{a ~ p_theta}[log p_theta(a) - log p_ref(a)]`.

**Sampling distribution:** the trajectory is generated by the theta-flow (lines 651, 667-668). The batch expectation is under `p_theta`.

**Sign:** `sum_kl = log p_theta - log p_ref`, not the reverse.

Both match. **This is forward KL, `KL(p_theta || p_ref)`.**


## Sign in the Actor Loss

```python
kl_loss = self.kl_weight * kl.mean()                                    # line 898
sac_loss = -q_min.mean()                                                # line 915
total = sac_loss + kl_loss + jac_loss + entropy_loss + vres_loss         # line 930
```

The actor minimizes:

```
L_actor = -E[Q] + lambda_kl * E[sum_kl] + ...
        = -E[Q] + lambda_kl * E[log p_theta - log p_ref] + ...
```

Positive coefficient on forward KL. Minimizing pushes `p_theta` toward `p_ref`, penalizing the policy for deviating from the reference.

Sanity check: when `v_res = 0`, `v_theta = v_ref`, so `a^k_inv = a^k`, `M^theta = M^ref`, and `sum_kl = 0`. The penalty vanishes.

Every sign in the chain is consistent: the change-of-variables minus, the `logdet_ref - logdet_combined` order on line 720, and the `+ kl_loss` on line 930.


## What slogdet Does

`torch.linalg.slogdet` returns `(sign, logabsdet)` where `logabsdet = ln|det(M)|`. On lines 711 and 717, the sign is discarded (`_`), so the code computes `ln|det(M)|` rather than `ln(det(M))`.

If `det(M) < 0`, the true log-determinant is complex-valued and the change-of-variables formula breaks. In practice this is safe because `M = I + J * dt` is a perturbation of the identity for small `dt`, keeping the determinant positive by continuity. If training destabilizes (large Jacobian eigenvalues or large `dt`), the determinant could silently go negative. A defensive check would be `assert (sign > 0).all()`.
